Methodology (so you can reproduce or challenge it)

  • Same data: points are generated from a fixed seed (mulberry32), so every library renders the identical set at a given count.
  • No basemap: tiles are disabled for all three, isolating point-rendering cost from network/tile work.
  • Same viewport: 800×500 for every run.
  • Same styling: filled circles, radius 3px, color #e0393e, no stroke.
  • Scripted camera: continuous circular pan at fixed zoom 11 (~0.5 Hz, ±0.015°), forcing a full redraw every frame.
  • Measurement: 1s warmup (discarded) then a 5s window; FPS = 1000 / mean(frame interval). Frame-time percentiles come from the same interval samples.
  • Leaflet uses L.canvas() + L.circleMarker (the fastest honest Leaflet approach; SVG is slower). Markers are inserted in async chunks with a 25s setup budget — if exceeded, the run is recorded as a setup timeout.
  • MapLibre uses a GeoJSON source + a circle layer on a blank style.
  • Rustyleaf uses PointLayer.add().

Numbers are hardware/browser specific — run it yourself. rAF caps FPS at your display's refresh rate (usually 60), so at light load libraries tie at ~60 and differentiate on p95 / worst frame time; at heavy load average FPS drops and separates them. This harness measures rendering throughput only — not features, ecosystem, or vector-tile support, where MapLibre and Leaflet are far more mature.
